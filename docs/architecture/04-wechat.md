# 微信平台约束

微信平台规则是跨小程序、后端和运维的硬约束。接口契约见 `../api/openapi.yaml`，本文集中列平台和隐私约束。

## 1. 约束清单

| 约束 | 内容 | 受影响端 |
|---|---|---|
| 登录链路 | `wx.login` + `code2Session`，见第 2 节 | 小程序 + 后端 |
| 合法域名 | request 只认备案域名 + HTTPS；后台提前配置白名单 | 小程序 + 运维 |
| 主体与类目 | 电商类目按主体和商品准备资质 | 运营 |
| 隐私 | 收集手机号、地址前展示隐私政策和用途 | 小程序 + 后端 |
| 审核话术 | 积分场景不出现“充值”“人民币”等不合规文案 | 小程序 |
| 发布链路 | 开发上传 -> 体验版内测 -> 提交审核 -> 发布上线 | CI + 小程序 |

## 2. 登录链路

```text
小程序 wx.login() 获取一次性 code
  -> POST /api/v1/auth/wx-login
  -> 后端调微信 code2Session（数据库事务外）
  -> 获取 openid + session_key
  -> 只使用 openid 识别用户
  -> 按首次登录规则创建用户和赠分
  -> 提交事务后签发买家 JWT
  -> 小程序保存 JWT，后续请求统一附加 Bearer
```

- `code` 只能使用一次；网络超时不能盲目重放同一个 code，客户端应重新调用 `wx.login()`。
- `session_key` 是微信服务端凭据，本期不写数据库、不下发、不写日志、不放入 JWT。
- 未来需要解密微信数据时，后端收到 `session_key` 后即时解密并丢弃；如确需持久化，必须单独设计密钥管理和轮换。
- `WX_APPID` 和 `WX_SECRET` 只存在服务端 Secret 中。
- `openid` 是当前小程序内的登录唯一键；业务表通过 `users.id` 关联，不把 openid 当作内部外键。

## 3. 用户资料和隐私

- `code2Session` 不提供昵称和头像；登录接口不把它们当作身份数据来源。
- 昵称和头像通过独立资料接口更新，服务端限制长度和格式。
- 收集手机号和收货地址前展示隐私政策、用途和保存期限。
- 手机号、地址、订单地址快照按敏感个人信息处理；日志、错误和监控中必须脱敏。
- 数据库连接、备份和图片卷使用加密保护，生产数据库不暴露公网。
- 订单履约和账务所需快照保留；注销时对个人字段脱敏，不破坏财务记录。

## 4. 发布与 CI

- miniprogram-ci 和代码上传密钥只在 CI Secret 中提供。
- 打 tag 自动上传体验版，人只负责体验验证和提审。
- 审核驳回不直接在生产修补，把审核意见转成变更提案后修改和重新提审。
- 发布前验证合法域名、隐私政策、登录、公开商品浏览和登录引导。

## 5. 预留

订阅消息（发货/退款通知）本期不做，后续启用时走变更提案，并重新评估用户授权和审核话术。
